# Write the draft yourself and stream it (when `nolang make` cannot be used)

Read this only when §S of `SKILL.md` (`nolang make`) cannot be used. For how to give links, follow "Most important" at the top of `SKILL.md`. For login see §L of `SKILL.md`; for specific assets, §M.
You write the script and the screens (draft src = `design.txt` and `timeline.txt`), and the NoLang server handles the voice, pictures, BGM and rendering.
All paths in this file are relative to this skill's directory.

## 1. Write the draft (in this order; no detours)

0. **Read the server's current docs** (before you start writing): `nolang draft docs` → the `dir` in the output is the directory of the docs (the grammar, the dictionaries, the samples). From here on, wherever this file says `<dir>/<name>`, read that file.
1. **Decide from the request**: the one sentence you want to get across, the aspect (`16:9` / `9:16`), the rough length (the draft itself sets it: aim at the seconds the request states; otherwise fit it to the content), the type (`concept` explainer / `data` numbers / `compare` comparison / `story` story / `cinematic` visual-led), and the language (the language you write the lines in = the one stated in the request, if any; otherwise the language of the request text). Do not ask back; proceed with the defaults, and tell the user the values you chose at the end.
2. **Read the grammar and one sample**: the grammar is the full text of `<dir>/spec.md` and, when the directory has it, the full text of `<dir>/core.md` (NoLang's own words — what CSS / GSAP do not have; these two are everything NoLang's own writers read). The other documents are dictionaries: open them only for what you need. Then read in full one sample from `<dir>/samples/` that is close to the video you are making (the title on line 1, the `見せる作り:` ("how it is shown") summary, and all of design.txt and timeline.txt). Take one of your type (`hf_<type>_*.md` or `<type>_NN.md`; line 1 of each file gives its topic and `canvas` size), in the same orientation as your video, and not on the same topic as the request (a sample on the same topic gets copied word for word). Read a second sample only when you need another model. Look at the scaffolds in `<dir>/scaffolds/` only to check the shape of the grammar.
3. **Only when using specific assets**: get a `ref` with §M of `SKILL.md`, and write it in the position given by `usage` in the response.
4. **Write** (design system first; stream each cut as you write it):
   - **Decide the structure before writing**: decide the cut names and contents (one line per cut) first, and put the heading `*** name` of every cut in timeline.txt, in order, before `nolang draft start` (a heading with nothing under it = a cut not written yet). `draft start` fixes the root and the list of cuts: a cut or a root line added after it never reaches the video, so a definition that only a later cut needs goes in that cut's own block. Each cut is submitted as soon as it is written, and a submitted cut cannot be fixed, so do not go back to earlier cuts while writing.
   - **Decide the design system once, at the root**: from "Style kits" in `<dir>/looks.md`, pick one that fits the mood of the request, and write `palette` `font` `fonts` `motion` `transition` at the root, plus a `def` (= class) for headings, body text, labels and boxes. Fit the values to the topic. The sample is a model of how to build (how scenes are put together, the components' `def`, motion, how to mark words) — do not copy its colors and fonts as they are.
   - Topic-specific things in the root: `image name = "…"` (a description of the reference image), the `bgm` description, `cast` (the voice description, in the language and tone of the request), `art` (art style). Do not write `lint off=…` or `# ` notes.
   - **Rebuild the cuts from the structure of the request**: split the flow of the request into cuts (5–8 cuts for 60 seconds; about 1–3 sentences of lines per cut), assign each cut a matching scene pattern from the sample, and write the text, lines and picture descriptions for the topic. Do not match the sample's number or order of cuts. Delete the scenes and `def`s you do not use.
   - Keep text short enough to fit its frame (the text length in the sample is a guide; text that is too long triggers check's `shrink_estimate`). Give the elements a new `#name` in each cut, and do not use the same name across cuts (except the root's `.sticky` items).
   - 1 cut = a `section#name` block in design + a `*** name` block in timeline (the names must match). Save them as `design.txt` and `timeline.txt` in a working directory (for example `./nolang-videos/<lowercase-english-name>/`).
   - **Writing order**: start streaming once you have written the root, every heading and the first cut (step 2 of §2), and after that submit each cut as soon as it is written. Do not submit only after writing everything (that makes the user wait several minutes until playback starts).

## 2. Stream it

1. **Log in**: §L of `SKILL.md`.
2. **Start streaming** (once the root, every heading and the first cut are written): `nolang draft start <dir> --title '<title>' --language <language of the lines: ja / en / …>` (`--language` is required; the aspect comes from `canvas` in design). It submits the root and the first cut. A draft or a cut with a DEFECT is not accepted, here and at every `nolang draft continue` (the output has `defects`): do what its `fix` says and run the same command again; submitted cuts cannot be fixed, so do not change them. If the connection drops and you do not know the result of a submission, just run the same command again.
3. **Notify** (always; before writing the second cut): once `nolang draft start` succeeds, **write the output's `tell_user` (the guidance sentence + the URL on the next line) as is in the body of your message to the user**. Playback starts within tens of seconds, and the rest extends as each cut is submitted.
4. **Stream the rest**: write the next cut (the lines under its heading in timeline.txt and its `section#name` in design.txt) and run `nolang draft continue <dir>`. Repeat this for every cut, in order. **Submit each cut within 900 seconds (15 minutes) of the one before, and the last one within about 40 minutes of `draft start`** — submit right after you write each cut; `nolang draft check` and `nolang draft stills` do not extend the time. When the time runs out, the draft closes and the video is finished with the cuts that arrived (it does not fail). The draft closes by itself when the last cut is submitted; add `--end` only to finish without writing the remaining cuts.
5. **Finish**: when the `nolang draft continue` of the last cut returns (`ended: true`), write the output's `tell_user` (the guidance sentence + the URL on the next line) and end the turn. Check for completion only when asked (`nolang status <video_id> --wait --timeout 540`, run again while it is still generating → on `completed`, tell the user it is complete, with the URL; the mp4 is `download_url`; also pass on the credit notice `copyright` — it must be shown when the video is published).
6. **On failure** (the `fix` of a refused `nolang draft continue` says the video takes no more cuts, or status is `failed`): that video is over. Review the draft (check that it does not break the rules in step 4 of §1), then delete `<dir>/stream.json` and remake it from start — at most once (add `--assets-from <that video_id>` to `nolang draft start` — it carries over the pictures that run made and the voices it chose, without remaking them). If it is still `failed`, stop and tell the user the video_id and that "check passed but generation failed" (it is often a server-side problem; ask the user to tell the administrator). **Do not make test videos to look for the cause** (for example, creating many versions with fewer cuts). For any other error, do what the output's `fix` says.

## 3. What else the draft commands do

The flags are in `nolang draft --help` and `nolang transcribe --help`, and each command's output says what to do next (`next`, or `fix` after an error).

- **Fix your own video and render it again, or write something new in a template's form**: `nolang draft pull <dir> <video_id or URL>` writes the saved draft to `<dir>/reference/`, and its `next` says how to go on (`--assets-from <video_id>` carries over that video's assets). Do not change a single character in the lines for pictures and voices you want to keep; for a picture you want to change, rewrite the description.
- **Cut and use brought-in audio**: `nolang transcribe <audio or video file or id>…` returns the utterance ledger (`brief`) and how to write `@clip`. Pass the returned ids to `nolang draft check`, `nolang draft submit` and `nolang draft start` as `--speech <id>[,<id>]` (the same value for all three). To run `transcribe` again, pass the id it printed (`REF <file> id=<uuid>` on stderr), not the file. If you only want to read the lines and times of a reference video, do not add `--speech` (NoLang synthesizes the voice).
- **Add moving footage (AI clips)**: add `--clip-seconds <seconds>` to `nolang draft submit` / `nolang draft start`; for how to write the pictures, read `ai_clips.md` in the `nolang draft docs` dir. Use it only for videos built mainly on real footage (cooking, vlogs, etc.) or for scenes where the user asked for moving footage.
- **Check the pictures before submitting**: after `nolang draft start`, `nolang draft stills <dir> [cut]` renders a cut you have written but not submitted yet as stills with the real pictures. Look at the images and do what its `next` says. Do not keep making trial renders just to look.
